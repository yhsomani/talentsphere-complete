Supersession: supersedes nothing. It is an additional, generated map. It does not edit ACTION_REGISTRY: that registry keeps its placeholder names `API-<module>-<verb>` until its owner applies the placeholder table in section 4. Linked from `13_API_EVENTS_AND_INTEGRATIONS/INDEX.md` by the documentation architect.

All content is **[TARGET]**. Generated by a script (kept outside the repository) that reads ACTION_REGISTRY, API_CATALOG, `openapi.yaml` and `openapi.addendum.yaml`; the script fails on any ACT whose placeholder has no entry. The catalog ids below are final; operationIds are copied from the contract files, never written by hand.

## 1. Status vocabulary and result

| Status | Meaning |
|---|---|
| OK | Every API the action needs has an `operationId` in `openapi.yaml` or `openapi.addendum.yaml` |
| CATALOGUED | Every API has a catalog row (`API_CATALOG.md` or `API_CATALOG_ADDENDUM.md`) but at least one has no OpenAPI operation yet (non-P0 domains; due before their work package exits) |
| MISSING | No operation and no catalog row can serve the action, or the action's semantics are undecided; the reason is in the Note column |
| CLIENT | The action calls no server operation (navigation, local setting, local draft) |
| DEFERRED | The action belongs to a deferred domain (networking, DOM-14, Ph4) and is out of the launch registries |

**CI rule (fail on unresolved):** the generator is the CI check `act-op-map`: it fails when an ACT row cites a placeholder with no mapping, when a mapped id is in neither catalog, or when the count of MISSING rises above the number recorded in this file. Until the check exists in CI, this file is regenerated in the contract review gate.
